# 探索記録とエンド後の再開（作者用）

`/player-record/` はプレイヤー用の控え。施設の通常メニューやサイト内検索には加えず、フィクション表記と著作表示の隣から開く。作中の通し番号・段階の266ページには含めない。表示を開くこと自体では、資料を提出したり結末を戻したりしない。

## 訪問とエンドの記録

実際に表示された登録ページだけを、種類・クエリを除いたパス・固定の題名・段階・最初と最後の記録日時で保存する。読み込み用の殻、権限不足の資料、まだ見ていないページは登録しない。同じページは種類とパスでまとめる。過去のブラウザー全体の履歴は取得せず、この機能で表示を確認したページから蓄積する。

リンク先は現在の探索状況とログイン名義で開く。昔の本文を固定したコピーではない。未到達ENDの番号や名前、未訪問の区分を一覧に先出ししない。既に結末のある旧ケースは、その結末を記録へ引き継ぐ。日付は記録日として表示し、取得できない昔の到達時刻を推測しない。

End1とEnd3は実際の受領後の画面、End2はZIPを添付して成立した受付控えと担当変更のお知らせに、本文とは分けた結果欄を置く。一般の問い合わせ受付と、原本の追加を待つ段階にはEND表示を出さない。朝倉名義のEnd2でも自分の受付控えは参照できるが、他の個人資料は閉じる。

## 任意で戻す範囲

現在の結末がある場合だけ、探索記録で確認を開ける。実行前に残すものと戻すものを表示し、キャンセルと通信失敗では状態を保つ。

| 戻す | 保持する |
| --- | --- |
| 現在のending、officeReceipt、auditPending | case ID、認証、contact、inquiryRecord、downloaded、truth、consoleTrial、到達済みEND、訪問記録 |
| 提出フォームの有効な世代・トークン | 欄外記録9件、名義ごとの既存閲覧記録 |

再開は同じケースのrevisionを一度増やす。Nodeでは同じケースに属するセッションだけのCSRFを更新し、他のケースを変更しない。静的版でも提出時の世代とトークンを検証し、リセット前からファイル読み込みを待っていた提出を後で完了させない。自動リセットや全保存領域の消去はしない。

## 保存方式

NodeとWorkerは既存のケース保存を使う。静的版はIndexedDBのreadwrite transaction内でケース全体を読み、同期的に変更して保存する。既存localStorageは初回の移行元と、その後の通知ミラー。認証や欄外記録など別の既存キーは消去しない。

古い画面が未知の値を書き戻した場合は、原文を同じブラウザー内のrecoveriesへ退避した後で正準のミラーへ同期する。初回は再読み込みを求め、再開後の結末やrevisionを古い状態へ戻さない。保存機能が使えない時は、保存済みのデータを変更せずエラーを示す。

## 共有

Xの投稿画面、端末の共有、本文のコピーを用意する。実際の投稿・送信はプレイヤーの操作で行う。共有本文と1200×630のPNGに含めるのは、到達済みから選んだEND番号、訪問件数、施設トップのURL、作品名と著作表示だけ。未エンドでは番号を表示しない。case、会員ID、呼称、個々の文書や訪問先は含めない。

PNGはブラウザーのcanvasで作成し、確認後に保存・画像を開く・対応端末での画像共有を選べる。画像生成API、外部フォント、外部の画像保存サービスは使わない。静的版のmodule/CSSは内容に応じたURLで参照し、会員と資料照会室の読み込み用画面にも一度ずつ読み込む。

## 確認

`tests/player-state.test.mjs` が状態とAPI、`tests/player-surface.test.mjs` が実表示マーカーと結果の条件を確認する。`scripts/playtest-player-record.cjs` は実際のログイン・ZIP取得・提出・任意再開を行う作者用の隔離試験。`scripts/playtest-console-tabs.cjs` は実測定を完了してからEnd3と再開を操作し、結果を保持することを確認する。初見での解法到達率や人間の所要時間を示す試験とは分ける。
